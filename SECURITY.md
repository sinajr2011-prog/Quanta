# Security Policy

## Reporting a vulnerability

Please do not publish sensitive vulnerability details in a public issue.

Report suspected security vulnerabilities privately to the repository
maintainers through the security contact configured for the repository.

When reporting, include:

- affected version or commit;
- affected component/file;
- concise reproduction steps;
- security impact;
- any safe mitigation you have identified.

Do not include real passwords, API keys, student records, national IDs,
private messages, or other personal data in a report.

## Supported releases

Security fixes are prioritized for the current supported release line.
Historical releases may not receive fixes unless maintainers explicitly state
otherwise.
